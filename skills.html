PARTIE 1C'est quoi un skill ?

Un skill est un dossier d'instructions que Claude va chercher seulement quand la tâche le demande.

Définition

Un dossier qui contient un fichier SKILL.md (des instructions en Markdown) et, au besoin, des fichiers de référence et des scripts. Claude le lit quand la demande correspond à sa description.

À quoi ça sert

Enseigner à Claude une méthode réutilisable : une procédure, un format de document, une façon de travailler propre à ton équipe. Tu l'écris une fois, il s'applique à chaque fois.

Pourquoi pas tout mettre dans le prompt ?

Parce que le contexte de Claude est limité et partagé. Un skill ne coûte presque rien tant qu'il n'est pas utile : c'est ce qui permet d'en avoir beaucoup.

PARTIE 2Anatomie d'un skill

Un dossier, un fichier obligatoire, et quelques lignes de réglages en tête.

# Arborescence type
mon-skill/
├── SKILL.md          # obligatoire : sert de sommaire
├── reference.md      # détails, lus seulement au besoin
├── examples.md
└── scripts/
    └── valider.py    # exécuté, pas lu
---
name: rapport-hebdo
description: Rédige le rapport hebdomadaire d'équipe au format interne.
  À utiliser quand l'utilisateur parle de compte rendu de semaine.
---

# Rapport hebdo
1. Rassemble les points de la semaine.
2. Suis le modèle décrit dans reference.md.
3. Exécute scripts/valider.py avant de rendre le résultat.
Le frontmatter

Le bloc entre les deux lignes ---, à la toute première ligne du fichier. Si le YAML est mal écrit, le skill se charge sans ses réglages.

Dans Claude Code

Tous les champs sont optionnels, seul description est recommandé. Le name prend par défaut le nom du dossier. Autres champs utiles : disable-model-invocation (usage manuel seulement), allowed-tools, context: fork (exécuter dans un sous-agent), paths.

Sur claude.ai et l'API

name et description sont obligatoires. name : 64 caractères maximum, minuscules, chiffres et tirets, sans les mots réservés « anthropic » et « claude ». description : non vide, 1 024 caractères maximum. Les autres champs que license, compatibility, metadata et allowed-tools sont refusés.

À ne pas présenter comme standard

Les dossiers scripts/ et des fichiers de référence sont montrés dans la documentation. Un dossier assets/ n'y est pas décrit comme une convention.

PARTIE 3Le chargement en 3 niveaux

Le principe clé pour scaler : Claude ne charge que ce dont il a besoin, au moment où il en a besoin. C'est la « progressive disclosure ».

Niveau 1 · au démarrageMétadonnées

name et description de chaque skill, toujours présents. Environ 100 tokens par skill.

Niveau 2 · au déclenchementInstructions

Le corps de SKILL.md, chargé quand la demande correspond. Moins de 5 000 tokens.

Niveau 3 · au besoinRessources

Fichiers de référence et scripts. Rien tant qu'ils ne sont pas lus. Un script exécuté n'ajoute que sa sortie.

Conséquence

Tu peux installer beaucoup de skills : chacun ne pèse que sa description tant qu'il ne sert pas. C'est donc la description qui devient la ressource rare.

Dans Claude Code

Une fois invoqué, le SKILL.md reste dans la conversation. Lors d'une compaction, la dernière invocation de chaque skill est rattachée de nouveau, dans la limite de 5 000 tokens par skill et 25 000 au total.

Piège

Les fichiers de référence doivent être cités depuis SKILL.md. Sinon Claude ne sait pas qu'ils existent.

PARTIE 4Où vivent les skills

L'endroit où tu poses un skill décide de qui peut l'utiliser.

EmplacementCheminQui l'a
Entreprise.claude/skills/ dans les réglages managésToute l'organisation
Personnel~/.claude/skills/<nom>/SKILL.mdToutes tes sessions
Projet.claude/skills/<nom>/SKILL.mdLe dépôt
Imbriquésous-dossier/.claude/skills/Ce sous-dossier (monorepo)
Pluginplugin/skills/<nom>/SKILL.mdLà où le plugin est activé
Priorité à nom identique

Entreprise, puis personnel, puis projet. Les skills de plugin portent un préfixe (/nom-plugin:nom-skill), donc ils n'entrent pas en collision.

Trois surfaces séparées

claude.ai (zip importé dans les paramètres, skills individuels, sans gestion centrale par un admin), l'API (téléversement via /v1/skills, partagé à tout l'espace de travail) et Claude Code (système de fichiers). Les skills ne se synchronisent pas entre ces trois surfaces.

PARTIE 5Scaler : les bonnes pratiques

Dix, trente, cent skills : ce qui change, c'est qu'ils se gênent entre eux. Voici comment l'éviter.

Taille et découpage

  • Garde SKILL.md sous 500 lignes. Dès que tu t'en approches, déplace le détail dans des fichiers de référence.
  • Une seule profondeur : SKILL.md pointe vers chaque fichier. Une référence qui cite une autre référence peut être lue en partie seulement.
  • Un fichier de plus de 100 lignes reçoit un sommaire en tête.
  • Range par domaine (reference/finance.md, reference/ventes.md) pour ne charger que le fichier utile.

La description décide du déclenchement

  • Dis ce que fait le skill et quand l'utiliser.
  • Écris à la troisième personne (« Traite des fichiers Excel… »), parce que la description est injectée dans le prompt système.
  • Mets des mots-clés précis. « Aide pour les documents » est trop vague.
  • Un skill se déclenche trop souvent ? Précise sa description, ou ajoute disable-model-invocation: true pour le réserver à l'usage manuel.

Éviter les chevauchements

Le risque

Une description trop large « vole » les déclenchements d'autres skills. Teste que les skills coexistent bien.

La méthode

Commence par des skills étroits. Regroupe-les ensuite en ensembles par rôle (par exemple « opérations commerciales ») quand les évaluations confirment que les résultats restent équivalents.

Scripts : exécuter plutôt que lire

  • Un script exécuté n'entre pas dans le contexte : seule sa sortie compte. C'est le bon choix pour les opérations déterministes.
  • Écris explicitement « Exécute scripts/x.py » ou « Lis scripts/x.py pour l'algorithme ».
  • Dans Claude Code, appelle les scripts avec ${CLAUDE_SKILL_DIR}.
  • Sur l'API : pas d'accès réseau, pas d'installation de paquets à l'exécution.

Tester avant de multiplier

  1. Écris les évaluations avant la documentation complète : mesure ce que Claude fait sans le skill.
  2. Rédige le minimum qui comble les écarts.
  3. Prévois au moins 3 évaluations par skill, sur les trois tailles de modèles (Haiku, Sonnet, Opus). Pour une équipe : 3 à 5 requêtes par skill, avec des cas où il doit se déclencher, ne pas se déclencher, et des cas ambigus.
Outils dans Claude Code

claude plugin eval exécute des cas de test et peut vérifier si le skill a bien été déclenché. claude plugin validate contrôle le frontmatter. /skill-doctor donne un rapport d'usage et de coût en contexte.

Versions

  • API : sans numéro de version, c'est toujours la dernière. Un nouveau téléversement change donc la production tout de suite. En production, épingle une version et garde la précédente en secours.
  • Plugins : le champ version de plugin.json est optionnel. S'il est défini, les utilisateurs restent dessus jusqu'à ce qu'il change.
  • Garde tes skills dans Git : relecture par pull request et retour arrière possibles.

PARTIE 6Distribuer et gouverner

À plusieurs, un skill est du logiciel : il se packagera, se versionnera et se contrôlera comme tel.

Plugin

Le paquet de distribution. Un dossier avec .claude-plugin/plugin.json qui regroupe skills, agents, hooks et serveurs MCP.

Marketplace

Le catalogue d'où on installe les plugins. Pour une organisation, les réglages managés peuvent enregistrer une marketplace (extraKnownMarketplaces) et forcer ou bloquer un plugin (enabledPlugins).

Garde-fous d'organisation

strictKnownMarketplaces (liste blanche), blockedMarketplaces (liste noire), disableSideloadFlags (refuse les plugins chargés à la main) et strictPluginOnlyCustomization (bloque les skills, agents, hooks et MCP qui ne viennent pas d'un plugin ou des réglages managés).

Mesurer l'usage

L'API Analytics (plan Enterprise) donne les installations et invocations par plugin. Une API d'usage des skills existe en bêta.

Sécurité

  • Audite un skill comme un logiciel : scripts, appels réseau (curl, requests, fetch), identifiants écrits en dur, chemins qui sortent du dossier (../), instructions qui cachent des actions.
  • Sépare l'auteur et le relecteur.
  • Sur Claude Enterprise, un scan de sécurité des skills est activable dans les paramètres de l'organisation (claude.ai et Cowork, pas l'API).
Règle qui doit toujours s'appliquer ?

Ne la confie pas seulement à un skill, qui reste une instruction que Claude interprète. Utilise un hook, qui est du code exécuté à coup sûr.

PARTIE 7Skill, MCP, sous-agent, CLAUDE.md…

Chaque outil répond à un besoin différent. Les confondre est l'erreur la plus courante.

OutilRôleCoût en contexte
CLAUDE.mdRègles « toujours faire X ». Moins de 200 lignes recommandé.Chargé en entier à chaque session
SkillSavoir ou procédure réutilisable, déclenchée à la demande.Description seule, puis contenu à l'usage
Sous-agentTâche verbeuse ou parallèle dans un contexte isolé. Seul un résumé revient.Contexte séparé
MCPConnecter Claude à des services et données externes.Schémas différés jusqu'à l'usage
HookCode exécuté à un événement. Déterministe.Nul
PluginEmballage pour distribuer skills, agents, hooks et MCP.Celui de son contenu
Elles se combinent

Un skill peut expliquer comment utiliser un serveur MCP, ou s'exécuter dans un sous-agent (context: fork). Un sous-agent peut précharger des skills avec le champ skills:.

Commandes slash

Le dossier .claude/commands/ est un format plus ancien. À nom égal, un skill l'emporte. Pour un nouveau plugin, utilise skills/.

PARTIE 8Limites chiffrées

Les seuls chiffres à retenir sont ceux de la documentation officielle. Ils changent selon la surface.

LimiteValeurOù
Corps de SKILL.mdMoins de 500 lignesRecommandation générale
Description à la création1 024 caractèresAPI et claude.ai
Description + when_to_use dans la liste1 536 caractères combinésClaude Code
Budget de la liste des descriptions1 % de la fenêtre de contexteClaude Code
Skills par requête20 maximumAPI
Après compaction5 000 tokens par skill, 25 000 au totalClaude Code
Si la liste déborde

Claude Code retire d'abord les descriptions des skills les moins invoqués. Le nom reste toujours listé, et un avertissement apparaît dans le journal de debug. Réglages : skillListingBudgetFraction, skillOverrides.

Nombre maximum de skills

Il n'y a pas de plafond officiel. La documentation recommande de limiter ceux qui sont chargés en même temps et de mesurer la précision du déclenchement avec des évaluations.

EN RÉSUMÉScaler en 7 règles

  1. Un skill, une tâche précise. Étroit d'abord, regroupé ensuite.
  2. La description dit ce que fait le skill et quand l'utiliser, avec des mots-clés précis.
  3. SKILL.md court (moins de 500 lignes), le détail dans des fichiers de référence cités depuis lui.
  4. Les opérations fiables dans des scripts, exécutés plutôt que lus.
  5. Des évaluations avant de multiplier : déclenchement, non-déclenchement, cas ambigus.
  6. Git pour l'historique, des versions épinglées en production, des plugins pour distribuer.
  7. Une revue de sécurité pour chaque skill, et un hook pour ce qui ne doit jamais être oublié.
